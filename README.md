# Чöвен (choven.by)

Сайт и система бронирования сплавов на байдарках по рекам Беларуси: лендинг на трёх языках, онлайн-бронирование с проверкой загрузки дней, личный кабинет клиента и админка для команды.

**Стек:** PHP 8.3 · Symfony 7.4 LTS · Doctrine ORM 3 / PostgreSQL 16 · Redis · Symfony Messenger · AssetMapper + Stimulus + Turbo · Docker.

---

## Возможности

**Для клиентов**
- Лендинг: слайдер, карточки сплавов, пакеты услуг, интерактивная карта маршрутов (Leaflet/OpenStreetMap), отзывы с рейтингом, FAQ, свежие статьи блога, форма «Перезвоните мне».
- Отдельная страница каждого сплава с ценой, рейтингом, составом пакета и маршрутом на карте.
- Бронирование без регистрации: проверка свободных мест, **дополнительные услуги** (трансфер, аренда палатки, фотограф — за заказ, за человека или поштучно, с ценой за день), **промокод или подарочный сертификат** в одном поле, живой расчёт стоимости.
- **Онлайн-предоплата** через bePaid (банковские карты, Apple/Google Pay, ЕРИП): обязательная или по желанию, процент задаётся в админке; оплаченная бронь подтверждается автоматически, неоплаченная в срок — отменяется.
- **Лист ожидания:** если даты заняты, можно оставить контакты — при отмене чужой брони придёт письмо со ссылкой на уже заполненную форму.
- Письмо-подтверждение с номером брони (`CH-XXXXXX`), ссылкой на бронь и файлом `.ics` для календаря.
- Страница брони по секретной ссылке: статус, расчёт стоимости, оплата, **перенос даты и отмена онлайн** (бесплатно — до N дней до поездки, с возвратом предоплаты), прогноз погоды на дни поездки, отзыв после поездки.
- Напоминание за 2 дня до поездки с **прогнозом погоды** (Open-Meteo) и советами по погоде.
- **Уведомления в Telegram и Viber:** клиент подключает бота кнопкой со страницы брони или из профиля — подтверждение, оплата, перенос, напоминание с погодой.
- **Подарочные сертификаты:** покупка онлайн на любую сумму, PDF для печати сразу на почту, тратится частями, действует год.
- **Блог** (Markdown, обложки, связанный сплав) и страница **«Вопросы и ответы»**, редактируемые в админке.
- Аккаунт: вход по email **или телефону**, подтверждение email, восстановление пароля, «запомнить меня», **двухфакторная аутентификация** (приложение-аутентификатор, резервные коды, доверенные браузеры), история броней (брони, сделанные раньше без аккаунта на тот же email, появляются после установки пароля через «Забыли пароль?» — так их не увидит тот, кто зарегистрировал чужой email), «забронировать снова», смена данных и пароля, язык писем, удаление аккаунта.
- Русский, белорусский и английский интерфейс и письма; язык определяется по браузеру.
- SEO: `hreflang`, canonical, `sitemap.xml`, `robots.txt`, Open Graph, schema.org (TravelAgency с рейтингом, WebSite, ItemList, TouristTrip с ценой, рейтингом и маршрутом, BlogPosting, FAQPage, BreadcrumbList, Product для сертификатов).
- Адаптивная вёрстка, доступность (ARIA, клавиатура, `prefers-reduced-motion`), адаптивные изображения AVIF/WebP.

**Для команды (админка `/ru/admin`)**
- Обзор: новые брони, звонки, отзывы, загрузка по месяцам, ближайшие сплавы.
- Брони: фильтры и поиск (номер, имя, телефон, email), CSV-экспорт для Excel (с доп. услугами, скидками и оплатами), создание брони по телефону, смена статуса с письмом клиенту, заметки команды, предупреждение о перегрузе дня, расчёт стоимости, платежи и **возврат денег одной кнопкой**.
- Календарь загрузки по дням с вместимостью и закрытыми датами; печатный «лист дня» для инструкторов со всеми группами и телефонами.
- Продажи: платежи с суммой за месяц, промокоды (процент или сумма, сроки, лимит использований), подарочные сертификаты (выпуск вручную, аннулирование, повторная отправка), дополнительные услуги, лист ожидания.
- Контент: каталог сплавов (тексты на 3 языках, цены, фото), редактор маршрутов карты, блог, вопросы и ответы.
- Модерация отзывов, заявки на звонок, пользователи и роли, выгрузка подписчиков рассылки (CSV).
- Настройки без программиста: контакты, мессенджеры, email для уведомлений, вместимость в день, закрытые даты, приём заявок вкл/выкл, предоплата и срок оплаты, срок бесплатной отмены и переноса, продажа сертификатов, обязательная 2FA для админов, баннер-объявление, счётчики Яндекс.Метрики и Google Analytics.
- **История изменений:** кто, когда и что поменял в админке (поле: было → стало), входы администраторов, возвраты денег.
- Недоставленные письма с повторной отправкой, журнал ошибок.

**Автоматика:** все письма и сообщения уходят в фоне через очередь с повторными попытками; новые брони, оплаты, переносы, отмены (с пометкой «нужно вернуть предоплату»), звонки, отзывы и лист ожидания дублируются в Telegram-чат команды; по расписанию — напоминания о поездке, закрытие прошедших сплавов с приглашением оставить отзыв, отмена неоплаченных броней, проверка листа ожидания, чистка устаревших данных.

**Защита:** ограничение частоты входа и форм (и подбора промокодов), honeypot от ботов, CSRF, проверка `Host` и прокси-заголовков, блокировка при одновременном бронировании последних мест (и одновременной трате одного сертификата), статус оплаты всегда перепроверяется через API платёжной системы, подписи вебхуков Telegram и Viber, защита CSV от формул, Markdown без HTML и `javascript:`-ссылок, автоудаление неподтверждённых аккаунтов, подписанные ссылки подтверждения, 2FA, журнал действий админов, заголовки безопасности на веб-сервере.

**Мониторинг:** ошибки уходят в Sentry или в собственный GlitchTip (`SENTRY_DSN`); `/health` — сайт и база, `/health/worker` — жив ли фоновый воркер и не застряла ли очередь (для UptimeRobot, Uptime Kuma и т. п.).

## Быстрый старт

Нужны Docker Desktop (или Docker Engine + Compose v2) и GNU Make. Всё запускается через `make`; полный список команд с описаниями — `make help`.

```bash
git clone https://github.com/ChewyPegasus/choven.by.git && cd choven.by
make init      # первый запуск: зависимости, сервисы, база с демо-данными, сайт
make open      # открыть сайт в браузере
```

Режим выбирается автоматически:

- **Linux / macOS (`MODE=docker`)**: всё работает в контейнерах (PHP-FPM, nginx, воркер, PostgreSQL, Redis, Mailpit). Сайт открывается на http://localhost:8080.
- **Windows (`MODE=local`)**: PHP запускается прямо в Windows, а в Docker остаются только PostgreSQL, Redis и Mailpit. Docker Desktop медленно монтирует файлы с диска Windows, так что в контейнере страница грузилась бы несколько секунд, а так — меньше 0,3 с. Сайт открывается на http://127.0.0.1:8000. Нужны PHP 8.2+ (`intl`, `pdo_pgsql`, `gd`, `mbstring`, `sodium`), Composer, Git for Windows и GNU Make 4+ (`choco install make`; Git Bash используется как shell автоматически).

Режим можно сменить на один запуск (`make start MODE=docker`) или навсегда, записав `MODE=docker` в файл `.make.local`.

| Что | Адрес |
|---|---|
| Сайт | http://127.0.0.1:8000 (Windows) / http://localhost:8080 (Docker) |
| Админка | `/ru/admin`: `admin@choven.local` / `admin12345` |
| Клиент | `user@choven.local` / `user12345` |
| Письма (Mailpit) | http://localhost:8025 |

### Основные команды

| Команда | Что делает |
|---|---|
| `make start` / `make stop` / `make restart` | запустить / остановить / перезапустить сайт и воркер (в фоне) |
| `make status` | что запущено |
| `make logs` | логи сервера, воркера и приложения в реальном времени |
| `make mail` / `make admin-open` | открыть Mailpit / админку |
| `make migrate`, `make migration` | применить миграции / создать новую по изменениям в сущностях |
| `make reset` | пересоздать базу с демо-данными |
| `make backup`, `make restore file=…` | дамп и восстановление базы |
| `make admin email=…` | создать администратора |
| `make jobs [job=reminders\|complete\|unpaid\|waitlist\|purge]` | запустить фоновые задачи вручную (напоминания, завершение прошедших заказов, отмена неоплаченных, лист ожидания, очистка) |
| `make images` | собрать адаптивные AVIF/WebP-версии всех фото |
| `make telegram-poll` | принимать сообщения боту без вебхука (локальная разработка) |
| `make failed` / `make retry-failed` | письма, которые не удалось отправить, и повторная отправка |
| `make cache` | очистить кэш |
| `make sql q="select …"`, `make psql` | запрос или консоль PostgreSQL |
| `make down` | остановить всё, включая контейнеры |

Настройки по умолчанию лежат в `.env`; свои значения — в `.env.local` (в git не попадает). Чтобы письма отправлялись сразу, без воркера, задайте `MESSENGER_TRANSPORT_DSN=sync://`.

В разработке оплата работает через **демо-страницу** (`PAYMENT_PROVIDER=demo`): кнопки «Оплатить» и «Отказаться» вместо банка. Включите предоплату в «Админка → Настройки», чтобы её увидеть. В продакшене демо-оплата не работает никогда.

## Продакшен

1. `make prod-env` (копирует `.env.prod.example` в `.env.prod.local`) и заполните секреты (`APP_SECRET`, пароль БД, `MAILER_DSN`, `DEFAULT_URI`, `TRUSTED_HOSTS`).
2. `make prod-build prod-up` — собирается самодостаточный образ на [FrankenPHP](https://frankenphp.dev) (Caddy + PHP в worker-режиме: ядро Symfony живёт в памяти между запросами, страница отдаётся за ~10 мс). Внутри код, зависимости, OPcache с preload и ассеты, заранее сжатые в brotli/zstd/gzip. Миграции применяются при старте контейнера `app`; контейнер `worker` из того же образа отправляет письма и выполняет задачи по расписанию.
3. HTTPS — один из двух вариантов:
   - **Caddy сам получает сертификаты Let's Encrypt:** `SERVER_NAME="choven.by, www.choven.by"`, порты 80 и 443 (TCP и UDP для HTTP/3) открыты наружу, `TRUSTED_PROXIES=127.0.0.1` (перед сайтом никого нет, заголовкам `X-Forwarded-*` не верим). Сертификаты хранятся в томе `caddy_data`.
   - **Свой прокси с TLS** (nginx, Traefik, Cloudflare): `SERVER_NAME` пустой, сайт отвечает по HTTP на `HTTP_PORT`. Прокси в частной сети или на том же хосте доверяются автоматически (`TRUSTED_PROXIES=private_ranges`); для внешнего (Cloudflare) добавьте его диапазоны IP.
4. Создайте администратора: `make prod-admin email=you@example.com`.
5. Резервная копия базы: `make backup PROD_MODE=1` (кладите в cron); восстановление — `make restore file=…`.

Число PHP-воркеров — `FRANKENPHP_WORKERS` (по умолчанию 4, у каждого своё соединение с базой), после `FRANKENPHP_LOOP_MAX` запросов (500) воркер перезапускается. Обновление со старой схемы (php-fpm + nginx): `make prod-deploy` — контейнеры `php` и `nginx` удаляются, тома `uploads`, `logs` и база остаются.

### Подключение сервисов

**Онлайн-оплата (bePaid).** Заключите договор с [bePaid](https://bepaid.by), в личном кабинете возьмите ID магазина и секретный ключ и задайте `PAYMENT_PROVIDER=bepaid`, `BEPAID_SHOP_ID`, `BEPAID_SECRET_KEY` (для оплаты через ЕРИП — ещё `BEPAID_ERIP_SERVICE_NO`). Сначала проверьте с `BEPAID_TEST=true` и тестовыми картами bePaid. URL уведомлений (`/payment/notify/bepaid`) передаётся автоматически, настраивать его в кабинете не нужно. Затем в «Админка → Настройки» укажите процент предоплаты и решите, обязательна ли она. Без настройки сайт работает как раньше — без предоплаты.

**Уведомления в Telegram.** Создайте бота у [@BotFather](https://t.me/BotFather), добавьте его в чат команды, узнайте `chat_id` (например, через [@getidsbot](https://t.me/getidsbot)) и задайте `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` — в чат будут приходить брони, оплаты и отмены. Чтобы тот же бот писал **клиентам**, добавьте `TELEGRAM_BOT_USERNAME` (без `@`) и `TELEGRAM_WEBHOOK_SECRET` (любая случайная строка) и один раз выполните `make prod-console c="app:bot:webhook telegram"`.

**Уведомления в Viber.** Нужен бот в [Viber Partners](https://partners.viber.com) (с 2024 года новые боты подключаются только по коммерческому договору с Viber): `VIBER_AUTH_TOKEN`, `VIBER_BOT_URI`, затем `make prod-console c="app:bot:webhook viber"`.

**Мониторинг ошибок.** Создайте проект в [Sentry](https://sentry.io) (бесплатного плана хватает) или поднимите собственный [GlitchTip](https://glitchtip.com) — он совместим с Sentry — и задайте `SENTRY_DSN`. Для доступности подключите внешний монитор (UptimeRobot, Uptime Kuma, Better Stack) на `GET /health` (сайт и база) и `GET /health/worker` (503, если фоновый воркер не работает больше 15 минут или очередь застряла).

**Двухфакторная аутентификация.** Каждый пользователь включает её в «Профиль → Безопасность». Чтобы обязать администраторов, включите «Требовать 2FA от администраторов» в настройках.

**Масштабирование и кэш.** Публичные страницы для гостей кэшируются целиком на 10 минут (Symfony HttpCache внутри приложения; заголовок `X-Symfony-Cache` показывает попадание). Любое изменение сплавов, маршрутов, отзывов, блога, FAQ, доп. услуг или настроек в админке сразу очищает кэш; вошедшие пользователи и посетители с сессией всегда получают свежие страницы. Сессии, кэш и блокировки в Redis, поэтому контейнеров `app` может быть несколько. Загруженные фото и их AVIF/WebP-копии (`uploads/_v`) лежат в томе `uploads`, копии фото из `assets/images` собираются при сборке образа.

## Контент и фотографии

- Сплавы, маршруты, тексты карточек и цены, доп. услуги, блог и вопросы-ответы редактируются в админке. Тексты блога и ответов пишутся в Markdown.
- Фото сплавов и обложки статей загружаются в админке (сжимаются до 1600 px и конвертируются в WebP; фоновый воркер делает версии 480–1600 px в AVIF и WebP, браузер сам выбирает нужную).
- Статичные фото сайта кладите в `assets/images/` (папка теперь в git):
  - `slider/kayaks.png`, `slider/view.jpg`, `slider/campfire.jpg` — слайды на главной;
  - `cards/*.jpg|jpeg` — обложки сплавов, созданных миграцией (`all-inclusive.jpeg`, `isloch-2day.jpg`, `svisloch.jpeg`, `isloch.jpg`, `svisloch.jpg`);
  - `gallery/*` — фотогалерея на странице «О нас» (выводится автоматически);
  - `og-image.jpg` (1200×630) — картинка для соцсетей.
  Пока файла нет, вместо него показывается аккуратная заглушка.
- Документы для скачивания: `assets/files/`.
- Тексты интерфейса: `translations/*.yaml` (ru/be/en), юридические тексты: `templates/legal/`.

## Разработка

```bash
make test                 # все тесты (unit, integration, functional) на реальном PostgreSQL
make test-unit            # только unit (также test-integration, test-functional)
make test-filter t=Booking  # тесты по имени
make coverage             # отчёт о покрытии в var/coverage (нужен Xdebug или PCOV)
make phpstan              # статический анализ, уровень 8
make cs-fix               # код-стайл (@Symfony)
make lint                 # проверка Twig, YAML, контейнера, схемы Doctrine, composer.json
make quality              # всё, что гоняет CI
```

Тестовая база пересоздаётся миграциями при каждом запуске (`SKIP_DB_RESET=1` — пропустить), каждый тест изолирован транзакцией. Отдельный тест рендерит все страницы на трёх языках и падает, если где-то остался непереведённый ключ.

```
  Entity/ Enum/        модель: User, Order (+ OrderExtra, Payment), Tour, RaftingRoute, Review, PromoCode, GiftCertificate,
                       Extra, WaitlistEntry, MessengerSubscription, Post, FaqItem, AuditLog, Setting

  Messenger/           боты Telegram и Viber, привязка чатов, уведомления клиентам
  Mailer/              AppMailer (все письма) и CustomerNotifier (письма + мессенджеры)
  HttpCache/           кэш страниц для гостей
  Security/            вход по email/телефону, проверка подтверждения email, voter для броней
  MessageHandler/      фоновые задачи; Schedule.php — расписание
  EventListener/       журнал изменений, очистка кэша страниц
  Validator/ Twig/ Repository/ Model/
templates/             Twig; emails/ — письма; admin/ — админка

```

### Почему без Kafka

Раньше письма шли через собственный продюсер/консьюмер Kafka, таблицы ретраев и cron. Для объёма небольшого сервиса это лишние Zookeeper и Kafka в проде и обязательное расширение `rdkafka`. Теперь письма и фоновые задачи обрабатывает Symfony Messenger поверх PostgreSQL: повторные попытки с экспоненциальной задержкой, очередь неудачных сообщений с просмотром в админке. Если нагрузка вырастет, транспорт меняется одной переменной `MESSENGER_TRANSPORT_DSN` (Redis, RabbitMQ, SQS).
